# README.md

## 目录结构

本仓库将个人开发过程与团队正式成果分开管理。个人先在 `Group/<成员缩写>/` 中完成实验和草稿，经过检查后再将可复现的代码、论文内容等合并到公共目录。

```text
GradMathModeling-D/
├─ Code/                  # 团队正式代码、实验脚本和结果生成程序
├─ Latex/                 # 团队正式 LaTeX 论文工程
│  ├─ figures/            # 论文图片
│  └─ sections/           # 按章节拆分的论文源文件
├─ Group/                 # 成员个人工作区
│  ├─ Lcn/
│  │  ├─ Code/            # 罗财能的代码实验区
│  │  └─ Latex/           # 罗财能的论文草稿区
│  ├─ Lcq/
│  │  ├─ Code/
│  │  └─ Latex/
│  └─ Lyz/
│     ├─ Code/
│     └─ Latex/
├─ D题/                   # D 题赛题材料
│  ├─ 数据/               # 原始数据和地理空间数据
│  ├─ 山区洪涝灾害下无人机运输与通信协同优化.docx
│  └─ 结果提交模板.xlsx
├─ 模板/
│  └─ GMCMthesis/         # 研究生数学建模竞赛论文模板及示例
├─ AGENTS.md              # 自动化协作与文件修改规则
├─ CONTRIBUTING.md        # 分支、提交、数据和论文协作规范
└─ README.md              # 项目概览与目录说明
```

### 目录职责

- `Group/<成员缩写>/` 用于保存个人实验代码、临时分析和论文草稿。成员目录下的 `Code/` 与 `Latex/` 应分别存放代码和论文内容，避免混放。
- `Code/` 用于保存团队确认采用的正式代码。合并前应保证依赖、运行入口和关键参数清晰，主要结果能够重新生成。
- `Latex/` 用于保存团队正式论文。正文按章节放入 `sections/`，图片统一放入 `figures/`；编译产生的辅助文件不应提交。
- `D题/` 保存赛题文档、提交模板和原始数据。原始数据原则上只读，清洗或转换过程应通过 `Code/` 中的脚本完成，处理结果需注明来源与生成方法。
- `模板/GMCMthesis/` 保存官方论文模板及示例，仅作为排版参考；正式论文修改应在 `Latex/` 中进行。

### 成果流转

1. 在自己的 `Group/<成员缩写>/` 目录中完成开发、实验或草稿。
2. 自检代码、数据来源、图表和论文结论，确保成果可复现。
3. 将确认采用的内容整理到公共 `Code/` 或 `Latex/` 目录。
4. 按 `CONTRIBUTING.md` 的要求提交分支并发起合并。
