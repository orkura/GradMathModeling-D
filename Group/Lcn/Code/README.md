# 第三、四题运输通信协同调度与独立分区配置

本程序读取仓库 `D题/` 下的原始题目、五个参数工作簿及30米DEM，生成80个不可拆货箱的运输与中继联合调度方案，并在导出前独立核验时间、能耗、库存、充电及连续通信。所有输出位于 `Group/Lcn/Results/Q3/`。

## 环境与运行

在仓库根目录运行。已经创建的 Conda 环境前缀为 `Group/Lcn/.venv`，可按完整路径激活，即使其未写入用户全局环境注册表也可使用：

```powershell
conda activate ./Group/Lcn/.venv
python -u Group/Lcn/Code/run_q3.py --starts 36 --refine-seconds 180
```

重新创建环境：

```powershell
conda env create --prefix ./Group/Lcn/.venv --file Group/Lcn/Code/environment.yml
conda activate ./Group/Lcn/.venv
python -u Group/Lcn/Code/run_q3.py --starts 36 --refine-seconds 180
```

也可直接使用环境解释器：

```powershell
./Group/Lcn/.venv/python.exe -u Group/Lcn/Code/run_q3.py --starts 36 --refine-seconds 180
./Group/Lcn/.venv/python.exe -B -m unittest discover -s Group/Lcn/Code/q3 -p "test_*.py" -v
./Group/Lcn/.venv/python.exe Group/Lcn/Code/run_q3.py --verify-only
```

`--seed 20260924` 固定随机序列。`--starts` 控制有限搜索次数，`--relay-grid-m 500` 控制悬停点初筛网格，`--spatial-step-m 100` 控制连续链路证书的初始轨迹分段长度。100米分段不是仅检查100米采样点：对每一整段使用传播距离界及全部相关DEM像元的遮挡判定。

本次交付使用上述180秒调度优化预算，分配给三个固定结构各60秒。CP-SAT采用单线程和固定种子，但按墙钟时间停止，不同计算机或负载下可能得到不同的可行解；精确核验已交付方案请使用 `--verify-only`，运行参数、源码和输入指纹见 `manifest.json`。

`--output Group/Lcn/Results/Q3_trial` 可以将实验输出放入其他目录。程序仅在完整方案独立验证通过后写入结果；失败以非零退出码退出，不能将旧输出视为新结果。

## 模型与求解范围

1. 加载并核对80个箱号、15个服务区、8架运输机、14组分机型共享电池、2架中继机及6组能源组件。31个货箱具有硬性截止时间。
2. 保留原始地理栅格，使用研究区中心的WGS84局部仿射米制坐标。水平直线穿过的全部像元用于计算最高地形，不能用两端海拔代替山脊高程。
3. 500米候选网格和节点位置结合150米、300米离地高度筛选中继。先检查回传链路，再通过轨迹采样筛选候选位置；候选筛选的采样通过本身不构成最终连续性证明。
4. 多起点构造搜索联合选择组批、机型、最多三个服务区的访问顺序、具体无人机、电池和开始时间。每个运输架次至多安排一个保底中继位置；中继可以在不同架次变更位置。
5. 已有同位置中继服务可以被多个运输架次共享；仅在不与后续资源任务冲突且能量允许时延长服务。不同任务组之间的分区独立性属于第四题，不在本程序中添加。
6. 不同搜索配置调整装载偏好、等待和能源代价、邻近节点组合及是否优先处理硬期限物资，部分配置还前瞻检查剩余硬期限任务。完整候选方案按加权延迟、联合完成时间、总能耗、总架次数的字典序比较。
7. 对至多三个有代表性的完整结构，用CP-SAT在整数秒网格上重新安排开始时刻与实体资源。资源占用向上取整、截止时刻保守取整；中继服务窗补充至多2秒舍入余量并重新计能耗。分别优化加权延迟和联合完成时刻。默认合计90秒求解预算，`--refine-seconds 0`可禁用。固定结构的最优性不等于原题全局最优。
8. 最终方案由独立验证器重建所有物理和资源量。依次审核整段通信证书与2秒网格复核。任何未证明连续覆盖的区间均不能标为通过。

这是有限候选集内的启发式可行方案搜索，不是连续空间全局最优证明。搜索失败表示当前候选集和构造策略未找到方案，不证明原题不可行。

## 计算口径与补充假设

统一使用米、秒、千克、立方米、kWh、kW；SOC在程序中为0至1，CSV中按列名转换为百分比。

- 题目给出等效航程与能耗结构但未完整展开水平和爬升能耗，补充采用 `E_hor=E_use*d/L(q)`、`E_up=(m_empty+q)*9.80665*h_up/(eta_up*3.6e6)`。
- 每一运输航段均按实际剩余货物质量计算，返航为空载。下降不额外计能耗，运输交接不添加题目未给定的悬停功率。
- 巡航海拔采用 `max(沿线最高DEM+50,起点作业海拔,终点作业海拔)`；后两项用于处理高悬停点，避免出现负爬升或负下降。服务区作业海拔以附件节点海拔加30米计算，网关以调度中心海拔加20米计算。
- 中继水平飞行采用巡航功率乘时间，爬升采用23.5kg计划总质量。到达悬停点至服务结束，包括30秒建链，都计入悬停功率与通信附加功率。
- 开始时刻表示地面准备开始。运输起飞前计固定准备和逐箱装载时间；同一服务区本次所载货箱统一在交接结束时完成交付。
- 运输机返航后可立即进入下一次准备；换电包含在准备时间内。中继机返航后另计300秒周转。能源资源返航后按题目两阶段SOC充电至100%才可再次投入。
- 按附件允许能源资源并行充电，未添加额外充电器/工位数量限制。题目未给中继接入容量和链路干扰模型，故不添加一对一服务或干扰限制。
- 双向链路预算分别为直连122dB、接入116dB、回传126dB。地形遮挡增加10dB损耗，而非直接断联。禁止中继间多跳。
- 通信CSV记录每个完整区间保证可用的保障者，称为“保底保障预约”。若区间内直连可用，实际系统优先使用直连；因此预约时长不是实际中继使用时长。`validation.json` 另给2秒复核中的直连/中继样本统计。

## 核验边界

几何证书对局部仿射坐标和分片常值DEM模型中的整个时间区间成立，并不证明真实地形的亚像元安全性或实际无线环境可用性。验算时间容差为1e-5秒、能耗容差为1e-6kWh；独立采样步长2秒，连续证书不确定时递归细分到0.25秒。保留这些边界，不能仅因没有采样到中断而声称连续通信。

源码分工：`data.py`解析输入；`physics.py`处理地形与链路；`solver.py`构造联合方案；`refine.py`重新优化固定结构的时序与实体分配；`verify.py`独立核验；`report.py`生成图表与报告；`run_q3.py`控制运行和证据记录。

## 第四题：固定第三题方案的独立分组

在仓库根目录运行，无需重新搜索第三题，也无需增加环境依赖：

```powershell
./Group/Lcn/.venv/python.exe -B -u Group/Lcn/Code/run_q4.py
./Group/Lcn/.venv/python.exe -B Group/Lcn/Code/run_q4.py --verify-only
```

运行测试时以代码目录为工作目录，以便导入相邻的 `q3` 和 `q4` 包：

```powershell
Set-Location Group/Lcn/Code
../.venv/python.exe -B -m unittest q4.test_q4 -v
```

`run_q4.py` 首先独立复核已保存第三题方案的飞行、时限、能量和连续通信，再读取固定任务分组。`--q3`可指定其他完整第三题方案，`--output`可指定仓库内其他输出目录。默认结果写入 `Group/Lcn/Results/Q4/`，不使用 `build/`。核验失败返回非零退出码，旧文件不能视为新运行成功。

### 固定条件与精确枚举

- 固定货箱组批、运输机型、访问顺序、准备及返航时刻、中继位置和服务时段、原通信保障关联；同型实体编号允许在组内重新分配。不允许删改、拆分或复制既定中继架次。
- 同一运输架次访问的服务区，以及同一中继架次保障的服务区，合并为不可拆单元，随后取传递闭包。当前方案得到6个单元，完整枚举31种两组分区和90种三组分区；组名置换不重复计数。不另加题目未要求的地理连通约束。
- 运输机占用至返航，电池至充满，中继机至返航后300秒周转完成，能源组件至充满。占用区间左闭右开，保留原始浮点时刻，严格比较端点；不以时间容差删除真实重叠。
- 每组每类资源最低配置等于占用区间的重叠峰值，贪心区间着色生成达到该下界的独立实体编号。各组编号互不相交。
- 主方案依次最小化分类库存缺口总数、配置总件数、工作量CV；均衡对照先最小化工作量CV，再比较缺口和总件数。每个运输或中继任务的工作量为准备开始至返航的时长，充电和返航后周转仅计资源占用。不同类型等权计件不等于采购成本。
- 精确最优仅适用于上述固定任务、不可复制中继和评价排序；第三题原方案仍是有限搜索得到的启发式可行解。

### 当前结果

| 分组 | 资源优先分区 | 配置总件数 | 相比共享池多需 | 分类库存缺口 | 工作量CV |
|---|---|---:|---:|---|---:|
| 两组 | S004单独成组，其余14区一组 | 30 | 3 | C型运输机1架、中继机1架 | 0.872908 |
| 三组 | S004、S006分别单独成组，其余13区一组 | 33 | 6 | A/B/C型运输机各1架、中继机1架、B型电池1组 | 1.159683 |

121个候选均存在分类库存缺口，因此这些配置必须补足所列资源才能按原时序独立执行。库存总数30件不能直接作为可执行判据。两组和三组的均衡优先方案分别需45、48件资源，库存缺口分别为16、19件，CV降至0.270042、0.640737，体现资源与均衡的取舍。
